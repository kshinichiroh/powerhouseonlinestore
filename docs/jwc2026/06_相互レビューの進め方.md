# 相互レビューの進め方（Claude ⇔ Codex ⇔ 岸さん）

最終更新: 2026-09-15

## なぜこうするか

この案件では、片方だけが見ていた箇所で必ず誤りが出た。逆に、**もう一方が別の資料を開いた瞬間に見つかっている。**

| 見つけた側 | 内容 |
| --- | --- |
| Codex → Claude | 試合コードの書き写しミス（`25グD15:30` → 正 `25グB15:30`） |
| Codex → 入力データ | `大会日程`シートが別大会の日程／DREAMSEEKERの試合が重複 |
| Claude → データ | スタッフが昨年度誌面に掲載されていた／掲載番号が123件不一致／WEST RIVER と RIVER WEST は別チーム |
| 岸さん → Claude | スタッフ不掲載という誤った断定／「プログラム番号」欄の混同／エントリーシートと申込書を別物と説明／JBA正本にスタッフがあること |

Claudeが単独で出した結論は、3回とも岸さんに止められている。**片方の出力をもう片方が検算する前提で回す。**

## 役割

| | 強み | 任せること |
| --- | --- | --- |
| Claude | 一次資料の横断（Drive・Gmail・過去誌面）、経緯の記憶、文面 | 何を正本とするかの決定、突き合わせ対象の指定、報告の検証、対外文面 |
| Codex | 実機のファイル、正確な機械処理、大量ページの描画確認 | 抽出・生成・検算・レンダリング確認 |
| 岸さん | 現物と現場の知識 | 最終判断、外部への送信可否、AIが両方とも間違えたときの発見 |

## Claudeが誤りやすい3つの型（実績あり）

### 1. 否定の断定

「〜はない」「〜できない」「〜は含まれていない」を、実物を見ずに書く。

- 「スタッフ名には照合できる正本がない」→ JBA正本に載っていた
- 「申込書にプログラム番号欄がある（＝全件そう）」→ 書式が混在していた

**対策：否定形・全称の主張を書く前に、実物を最低1件開く。開けないなら「未確認」と書く。**

### 2. 二次資料での断定

台帳・検証メモ・列名を根拠に、一次資料を見ずに結論を出す。

- 検証シートの「スタッフ情報は収録していない」→ 掲載方針だと誤読
- 「整理番号」という列名 → 掲載番号だと誤認

**対策：誌面に出る判断は、必ず一次資料（昨年度の完成誌面・原本PDF・要項）で裏を取る。**

### 3. 手作業の転記

手で書き写した値を、出典と1対1で照合しないまま使う。

- 試合コード133件のうち1件が誤り。日付と会場の整合チェックではコート記号の取り違えを検出できなかった。

**対策：手で書き写した値は必ず出典と機械照合する。整合性チェックは照合の代わりにならない。**

## 作業指示（Claude → Codex）に必ず入れるもの

1. **入力の正本と、その見分け方。** 似た名前のファイルがあるなら、中身で見分ける方法を書く。
2. **突き合わせの相手と期待値。** 「〜と全127件一致するはず」のように、数で書く。
3. **停止条件。** 1件でも合わなければ止めて報告、を明示する。
4. **推測の禁止。** 読めない・判断がつかないものは `要確認` として残させる。埋めさせない。
5. **禁止事項。** 外部送信・共有の禁止、個人情報の抽出禁止、コミット禁止。
6. **Claudeに確認してほしい点を書かせる欄。** 判断で処理した箇所を必ず挙げさせる。

## 報告（Codex → Claude）に必ず入れるもの

1. 入力ファイルの所在とSHA-256、複数ある場合はどう見分けたか
2. 突き合わせの結果（一致件数／不一致の一覧）
3. 検算値
4. **自分の判断で処理した箇所と、その根拠**（例：DREAMSEEKERの重複を残存データと判断した）
5. 生成物のパスとSHA-256

## Claudeが報告を受けたときにやること

報告を読むだけで終えない。**必ず次を行う。**

1. **Codexの判断を一次資料で独立に検証する。** Codexが判断で処理した箇所は、Claude側で別の資料から裏を取る。
   - 例：DREAMSEEKERの重複 → 公式トーナメント表PDFに `25グC11:00` がないことを確認した
   - 例：大会日程シートの日程 → 要項第6項と照合し、別大会だと確認した
2. **報告されなかったものを疑う。** 期待した件数の内訳が出ていない、要確認が0件、といった「きれいすぎる報告」は追加で確認する。
3. **Claude側の成果物に同種の誤りがないか点検する。** Codexが誤りを1件見つけたなら、同じ作り方をした箇所を全部見直す。
4. **岸さんに渡す前に、判断が要る点を明示する。** 「問題ありません」だけで終えない。

## 判断ログ

事実ではなく**判断**をしたときは、`03_やり取りの記録.md` に1行残す。

- いつ／誰が／何を選んだか／何を根拠にしたか／退けた選択肢

あとから「なぜこうなっているのか」を追えるようにするため。
この案件では、判断の経緯が残っていなかったせいで同じ確認を何度も往復した。
