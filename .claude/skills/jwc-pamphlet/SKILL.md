# JWC パンフレット制作の対応

## 最初に読むもの

必ず以下を読んでから回答・作業する。ここに書かれていることを推測で上書きしない。

0. **`docs/jwc2026/08_いまここ.md` — 最初にこれを読む。** いま何で止まっているか、
   何が済んでいて何が宿題か。会話の履歴は引き継がれないので、ここが唯一の現在地。
   **状況が動いたら必ずこのファイルを更新する。古いまま放置しない。**
1. `docs/jwc2026/00_パンフレット制作ルール.md` — 確定済みの制作ルール（これが正）
2. `docs/jwc2026/05_正本データの所在.md` — どのデータの正本がどこにあるか

4. `docs/jwc2026/01_素材ステータスと定型回答.md` — 「データ未着」照会への回答手順と定型文
5. `docs/jwc2026/02_トーナメント表の読み方.md` — 試合コードの凡例
6. `docs/jwc2026/03_やり取りの記録.md`
7. `docs/jwc2026/07_購入申込の案内が届かない場合.md` — 「案内が届かない」照会への手順 — いつ何を確定したか

## 基本方針

**同じ照会を往復させない。** 相手からの質問には、根拠（台帳の行・便番号・受付日）を添えて
一度で確定的に答える。「確認します」で止めず、台帳を引いて結論まで書く。

## 「案内メールが届いていない」と言われたとき

**謝る前に送信記録を引く。** 手順は `07_購入申込の案内が届かない場合.md`。
バウンス検索には `in:anywhere` を必ず付ける（Gmailがバウンス通知をゴミ箱へ入れることがある）。
送信済み・バウンスなしなら配信は成功しており、迷惑メールフォルダの可能性が高い。

## 「データが未着です」と言われたとき

1. 早合点して謝らない。まず台帳を引く。実際に未提出であることはほとんどない。
2. 確認順は `01_素材ステータスと定型回答.md` の手順に従う。
3. 「広告不要」「写真なし」「チーム名のみ」は **確定状態であり未提出ではない**。そう明言する。
4. 似た名称の別チームの取り違えを疑う（WEST RIVER と RIVER WEST など。ルール9を参照）。
5. 回答には 受付日・入稿便・格納フォルダ を必ず書く。

## 報告することがあるなら、止まる（岸さんの常設指示）

**何か報告しなければならないことが出てきた場合、メールや連絡をしてはいけない。前に進めてはいけない。**

2026-09-15に岸さんから明示された指示で、以後ずっと有効。気づきを見つけたら、
**それを抱えたまま作業を続けない。** 岸さんへ報告して、判断を待つ。

- 対象は**外部への送信・共有**（メール、Drive共有フォルダへの格納、権限の変更）。
- **リポジトリへの記録とコミットは止めない。** むしろ報告と同時に残す。
- 「些細だから」と自分で握りつぶさない。**握りつぶした結果が上積みの誤りになる。**

## メール下書きは持ち越さない

**作ったらその場で送る。送らないなら消す。** 下書きは作った時点の事実で固まり、時間が経つと嘘になる。
残すなら本文冒頭に「※この下書きは YYYY-MM-DD 時点の内容です」と入れる。

送信直前に必ず確認する。**「格納しました」「お渡しします」と書いたなら、実物を見て確かめる。**
リンク先のフォルダを開いて中身があるか見る。宛先が3アドレスか見る。方針が変わっていないか見る。

2026-09-16、前日の下書きが「格納いたしました」と書いたまま残っていた。実際は空フォルダだった。

## 絶対に変えない判断

- 誌面のチーム名は **JBA帳票の登録名**。トーナメント表PDFやフォルダ名の表記ではない。
- **例外はトーナメント表（組合せページ）だけ**（2026-09-15 岸さん決定）。組合せは既に一般公表済みのため
  `ゴッド ドア`（男子59・女子8）と `HyogoForce`（女子32）を**そのまま印字する**。
  チーム紹介ページ・メンバー表は `ゴッドドア`／`Hyogo Force`。**1冊の中で2通りになるが意図的。**
  ダイコロ様には「統一しないでください」と明示して伝える。この例外を他へ広げない。
- チーム紹介文は **入れない**（写真／ロゴ・チーム名・名簿のみ）。
- **スタッフは掲載する。** HC／AC／チーム責任者／トレーナー／チームスタッフ／帯同審判①②／帯同MC。
  出所は大会エントリーシート。「掲載しない」と答えてはならない（2026-09-15に誤答しかけた事故）。
  個人情報（電話番号・メール・住所・JBAメンバーID）を入稿データから外すこととは別の話。
- **エントリーシートにHCの記載がないチームは、JBA正本のHCをそこに記載してよい**
  （2026-09-15 喜録先生の電話承認）。補ってよいのはHCだけで、他の役職には広げない。
- **役職ラベルが大会申込書・JBA正本の両方で空欄なら、コーチライセンスで決める**
  （2026-09-16 喜録先生の電話承認）。**持っている先生がHC、持っていない先生がAC。**
  該当は女子27 明石市立二見中学校の1チームのみで、**山本 淳一＝HC（JBA公認D級）／
  三宅 祥平＝AC（コーチライセンス空欄）**で確定。これで役職の要確認は**0件**になった。
  **審判ライセンスと混同しない**（三宅氏の `JBA公認B級審判` は帯同審判のライセンス）。
  **ライセンスの等級は誌面に出さない。** 役職を決める材料であって掲載項目ではない。
  **誌面のHCの決め方**：大会申込書にあれば大会申込書、無ければJBA正本、両方無ければ岸さんの指名
  （女子46 RC＝西岡 達也）。1人が複数の役職で並ぶのは2025年度の誌面でも普通なので、それを理由に止めない。
- **「TeamJBAはHCが必須入力」は誤り。** JBA正本の125チーム中、ヘッドコーチ区分があるのは88チーム、
  ないのが37チーム（2026-09-15 全数集計）。**JBA正本に「HCがいないはずがない」と考えてはならない。**
- 2025年度の誌面は**人がいない役職の行を省いている**。HCが決まらないチームはHCの行が出ないだけで、
  空欄のラベルは残らない。
- **女子46 RC のHCは 西岡 達也。岸さんの指名であって正本由来ではない**（大会申込書・JBA正本のどちらにも
  HCの記載がない唯一のチーム）。外部に「正本にそう書いてあった」と答えてはならない。
- **同姓は同一人物の根拠にならない。** チームには親子・兄弟が普通にいる
  （男子32 U14 ゴッドドアの魚住は母子）。同姓の2名を表記ゆれとして1人にまとめない。
  JBAメンバーIDが両方にあれば、IDの一致・不一致で判定する（IDの数字は成果物に残さない）。
- 選手名簿は **No.／名前／学年／身長／学校名** の5項目・この順序。
- 素材受付は **第19便（2026-09-11）で終了**。以降の追加・差し替えは受け付けない。
- 共通広告は **1点のみ配置**。チームごとに重複配置しない。

## Windows Codex への依頼

Codexへの指示は **`docs/jwc2026/次の作業.md` に書く。** 岸さんが貼るのは固定の1行だけで、
文面は変えない。指示を変えたいときはこのファイルを更新する。

Codexから報告が来たら、読むだけで終えない。`06_相互レビューの進め方.md` の

## 断定する前に実物を見る

次の3つは、この案件で実際にやらかした型。書く前に止まる。

1. **否定の断定**（「〜はない」「〜できない」「〜は含まれていない」）と、
   **肯定の断定**（「〜がある」）も同じ。
   → 実物を最低1件開く。開けないなら「未確認」と書く。
   **別の年度・別の入手経路のファイルで見たことを、今回の現物の根拠にしない。**
   （例：2022年度のTeamJBA直接ダウンロード版が綺麗に読めた → 2026年度のスキャン版にも
   テキスト層があると誤断定した。綺麗に読めることはテキスト層の証拠にならない）
2. **二次資料での断定**（台帳・検証メモ・列名を根拠にする）
   → 誌面に出る判断は一次資料で裏を取る。
3. **片方の資料だけで結論を出す**
   → 大会申込書とJBA正本のように出典が2つある話で、片方に欠落を見つけたら、**結論を書く前にもう片方を見る。**
   2026-09-15、エントリーシートのHC欄が空欄の6チームを見て「コーチがいない＝没収試合」と断定し
   競技側へのエスカレーションまで提案した。JBA正本を見れば否定できた。
   さらにその後、岸さんから聞いた「TeamJBAはHC必須」という前提を裏も取らずにルールへ書き込み、
   全数集計で37チームにHC区分がないと判明して撤回した。**人から聞いた前提でも、
   ルールとして固定する前にデータで数える。**
   **欠落を見つけたときほど、それが「現実の欠落」か「その資料での欠落」かを区別する。**
4. **手作業の転記**
   → 手で書き写した値は出典と機械照合する。整合性チェックは照合の代わりにならない。
5. **「見つかりません」「0件でした」という報告**
   → **ファイルが無いことの証明ではなく、その検索語で出なかったことの報告。検索語を疑う。**
   2026-09-16、Codexが「D:／C:／G:／Drive の全ドライブ検索で0件。Excel2点は消失」と報告した。
   実際はファイルは存在しており、**複数形の `outputs` を検索対象から外していた**だけだった。
   Claudeはこれを受けて「worktree破棄が最有力」と書いたが、これも誤りだった。
   **不在の報告を受けたら、探した場所ではなく「どう探したか」を聞く。**

## 呼び名を勝手に増やさない

「エントリーシート」「参加申込書」「大会申込書」は **すべて同じ書類**（チームが記入するExcel）。
呼び分けたり、別の書類として扱ったりしない。2026-09-15にこれを別物として説明し、
岸さんを混乱させた。書類の同一性が怪しいと思ったら、まず実物のファイル名を確認する。

## 個人情報

- 選手名簿（氏名・学年・身長・学校名）は **このリポジトリに置かない**。正本はJBA帳票とDrive共有フォルダ。
- 電話番号・メールアドレス・住所・JBAメンバーIDは **入稿データにも含めない**。
- 素材台帳には代表者名・連絡先が入っているので、抽出するときは
  チーム名・男女・写真／ロゴ／広告の有無のみに絞る（`tools/build_xlsx.py` の実装を参照）。

## 入稿用Excelを作るとき

`tools/build_xlsx.py` を使う。生成物は2点。

- `JWC2026_トーナメント表_データ版_YYYYMMDD.xlsx`
  大会概要／日程・会場／会場コード凡例／試合コード一覧／男女の組合せ／表記ゆれ／制作ルール
- `JWC2026_チーム紹介メンバー表_チーム別シート版_YYYYMMDD.xlsx`
  目次／全体データ（1行1名）／**チーム別シート**（デザイナー様の要望。`M{番号}_` `W{番号}_`）／掲載対象外／制作ルール

必ず守ること:

- 両ファイルに `99_制作ルール` シートを入れる。ルールを誌面側にも常駐させるため。
- チーム別シートは必ず作る。デザイナー様はチーム単位で作業する。
- 数が合っているか検算してから渡す（チーム数・選手数を `data/` の集計と突き合わせる）。
- **手で書き写した値は必ず出典と機械照合する。** ただし **`25グD15:30` は正しい値。触らないこと。**
  2026-09-15に「`25グD15:30` は `25グB15:30` の誤りだ」という報告を受けて直したが、
  **その修正自体が誤りだった。** 翌日、ダイコロ共有フォルダの公式PDFをClaudeが直接読み、
  男子79件中78件が完全一致、唯一の差が本件で、**公式PDFは `25グD15:30`** と確認して元に戻した。
  教訓は2つ。**①「転記ミスを見つけた」という報告こそ、一次資料に当たって確かめる。**
  ②構造的な検算（重複なし・コート時刻衝突なし）は**どちらの値でも通る**ため、検算では捕まらない。
  照合は出典そのものと1対1で取ること。
- 共有はDriveの共有フォルダ。メール添付はしない（版の取り違え防止）。

## 返信文の型

宛名 → 用件の一覧 → 項目ごとに「結論 → 根拠（受付日・入稿便・フォルダ）→ 誌面での扱い」
→ 今後のためのルール参照先、の順で書く。相手が再質問しなくて済む粒度にする。
